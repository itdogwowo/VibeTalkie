# VibeTalkie 總計畫書

**版本**：v1.0（決策前）
**範圍聲明**：AI 能力**只做語音轉文字（ASR）**，不做 LLM 糾錯、不做 Agent、不做螢幕理解。

> ℹ️ **硬體事實已從本檔抽離** → 一律以 [`hardware.md`](hardware.md) 為準，本檔不再重複描述硬體。
> 本檔保留為**計畫與決策的來源**（目標、技術棧候選、測試規程、里程碑、風險）。

---

## 1. 專案目標

| 項目 | 內容 |
|---|---|
| 產品 | 一支藍牙音訊麥克風 + 鍵盤型按鍵 → 自己的桌面軟體 |
| 核心行為 | 按鍵按下開始錄音 → 放開結束 → 本地/雲端語音轉文字 → 自動輸入目前視窗 |
| 平台 | Windows 10/11、macOS、Linux（X11 優先，Wayland 記錄限制） |
| AI 能力 | **僅 ASR**：語音 → 文字（含標點、熱詞替換） |
| 隱私 | 預設全本地辨識、錄音檔辨識後刪除、零強制上傳 |

**明確不做（v1）**：

- 不做 LLM 整理/改寫/回覆
- 不做記憶、知識庫、技能、螢幕理解
- 不做自訓練語音模型（使用開源模型權重 + 開源推理引擎）
- 不寫 BLE 藍牙驅動（硬體走標準音訊 + 標準 HID 鍵盤）

## 2. 硬體假設（Phase 0 必須驗證）

> 📌 **實際驗證狀態已移至 [`hardware.md`](hardware.md) §4。** 本節只保留假設清單。

| 假設 | 驗證方法 |
|---|---|
| 麥克風以「標準藍牙音訊輸入裝置」出現在系統 | 列舉音訊輸入裝置，找到其名稱/VID/PID |
| 按鍵是 HID 鍵盤，按下送出某個鍵碼、放開停止 | 鍵盤事件記錄器，記錄真實鍵碼 |
| 裝置本身**不**內建辨識直接打字 | 記事本中按鍵，觀察是否自動冒出文字 |
| 麥克風支援 16 kHz 或可被系統重採樣 | 各平台測試錄音檔取樣率 |

> 🔴 **架構分支點已觸發（P0 實測）。** 原廠工具「閃電說」(`shandianshuo`)
> 正在執行並會注入按鍵事件，且綁定了其中一顆按鈕為 Control 鍵。
> 這不是「裝置自己會打字」，而是**原廠軟體**會打字。
> 詳見 [`hardware.md`](hardware.md) §8 —— 這件事會改變產品定位。

## 3. 系統架構

> 📌 **完整架構已移至 [`architecture.md`](architecture.md)**（含模組契約、狀態機、錯誤處理）。

```
┌─────────── UI：裝置選擇 / 按鍵綁定 / 設定 / 歷史 / 狀態燈 ───────────┐
└──────────────────────────────┬──────────────────────────────────────┘
                    事件總線（狀態: IDLE→RECORDING→PROCESSING→INSERTING）
┌──────────┬─────────────┬──────────────┬──────────────┬─────────────┐
│ DeviceMgr│ AudioCapture│     VAD      │    ASR       │  TextOutput │
│ 列舉音訊  │ 指定裝置錄音 │ 頭尾靜音修剪  │ sherpa-onnx/ │ 剪貼簿貼上→  │
│ 裝置     │ 16k/mono/f32│ 保留前後 300ms│ whisper.cpp  │ 逐字輸入    │
└──────────┴─────────────┴──────────────┴──────────────┴─────────────┘
                    共同：Config(TOML) / Hotkey / Tray / Log
```

**互動流程**：

1. 使用者把游標放進目標輸入框
2. 按住麥克風按鍵 → 全域熱鍵觸發 → 開始從指定麥克風錄音
3. 放開按鍵 → 停止錄音 → VAD 修剪頭尾靜音 → ASR → 文字
4. 注入文字：先備份剪貼簿 → 寫入 → `Ctrl/Cmd+V` → 還原剪貼簿；失敗則逐字鍵盤輸入

## 4. 三個候選技術棧

### 4.1 Rust + Tauri 2（正式候選，預期勝出）

| 面向 | 內容 |
|---|---|
| 核心依賴 | `cpal`（錄音）、`rubato`（重採樣）、`global-hotkey`（熱鍵）、`enigo`+`arboard`（注入/剪貼簿）、`sherpa-onnx`（ASR，走 C API 或現成 binding）、`tray-icon`、`serde`/`toml` |
| UI | Tauri 2 + Svelte/React（TypeScript） |
| 優勢 | 單一小安裝包（約 20–40 MB）；三平台原生支援齊全；記憶體低；打包生態成熟；AI 對 Rust crate 訓練資料充足 |
| 已知限制 | 編譯時間較長；`enigo` 在 Wayland 注入受限；onnxruntime/sherpa 原生庫需按平台捆綁；Rust 學習曲線較高 |
| Vibe Coding | 中等：錯誤訊息硬但明確，適合「小步 commit」 |
| 預期得分 | 高 |

### 4.2 Python（探路工具，不建議做正式產品）

| 面向 | 內容 |
|---|---|
| 核心依賴 | `sounddevice`/`PyAudio`（錄音）、`numpy`/`scipy`（重採樣）、`webrtcvad`/`silero-vad`、`faster-whisper`（CTranslate2）或 `whisper.cpp` binding、`pynput`/`keyboard`（熱鍵）、`pyperclip`+`pyautogui`（注入）、PySide6（UI） |
| 優勢 | 開發最快，最適合反向驗證硬體；ASR 生態最好；AI 寫 Python 最穩 |
| 已知限制 | PyInstaller 三平台打包痛苦、常被防毒誤報；啟動慢、記憶體大；全域熱鍵/注入在 macOS TCC 與 Wayland 下不穩；無法做到單檔小安裝包 |
| Vibe Coding | 最快 |
| 預期得分 | 原型高、產品低 |

### 4.3 Go（備選，驗證 cgo 限制）

| 面向 | 內容 |
|---|---|
| 核心依賴 | `malgo`（miniaudio 綁定）或 `gordonklaus/portaudio`（錄音）、`go-hook`/`robotgo`（熱鍵+注入）、whisper.cpp 或 sherpa-onnx 的 cgo 綁定、Wails v2 或 Fyne（UI） |
| 優勢 | 編譯快、單一靜態二進位、併發簡單、Wails 開發體驗接近 Tauri |
| 已知限制 | 關鍵庫幾乎都是 **cgo 包裝** → 跨平台交叉編譯難（需各平台工具鏈）；音訊/熱鍵庫維護度參差；ASR 綁定要自己寫 C 橋接；AI 對這類組合範例少 |
| Vibe Coding | 中等偏慢，cgo 錯誤訊息不友好 |
| 預期得分 | 中（能否跨平台打包是決勝點） |

## 5. 測試先後次序（重要）

| 輪次 | 棧 | 時間 | 目的 | 產出 |
|---|---|---|---|---|
| **第 1 輪** | **Python** | 2–3 天 | 最快鎖定硬體真相 + 建立基準線 | 硬體報告、基準錄音檔、20 句測試集 |
| **第 2 輪** | **Rust + Tauri 2** | 1–2 週 | 正式候選，驗證完整鏈路與三平台打包 | Rust Spike 報告 + 安裝包 |
| **第 3 輪** | **Go** | 1–2 週 | 驗證 cgo/交叉編譯是否為致命傷 | Go Spike 報告 |
| 決策 | — | 1 天 | 依評分表選正式棧 | ADR 決策紀錄 |

**為何 Python 排第一**：它贏不了產品，但 2 天就能確認「麥克風能不能錄、按鍵送什麼碼、ASR 準不準」，避免用 Rust/Go 花一週才發現硬體假設錯誤。

**若你想照原順序 Rust → Python → Go 也可**，代價只是硬體問題的發現時間晚一週。

## 6. 三棧統一 Spike 測試規程（同一套測試，公平比較）

每個棧必須通過同一組 T1–T7，記錄同一份表格（見 [`spike/`](spike/)）。

| 編號 | 測試 | 方法 | 通過門檻 |
|---|---|---|---|
| T1 | 裝置列舉 | 列出音訊輸入裝置名稱/VID/PID | 能看到藍牙麥克風 |
| T2 | 指定裝置錄音 | 錄 5 秒 16 kHz/mono WAV | 回放是該麥克風聲音 |
| T3 | 全域熱鍵 | 監聽 F9（或裝置鍵碼）按下/放開 | 三平台事件正確 |
| T4 | ASR 準確率 | 20 句固定測試集（中文為主 + 英文/數字） | 中文句準確率 ≥ 95% |
| T5 | ASR 延遲 | 5 秒語音，本地模型 | 端到端 ≤ 1.5 秒 |
| T6 | 文字注入 | 記事本/TextEdit/gedit + 1 個聊天 App | 記事本 100% 成功 |
| T7 | 打包安裝 | 乾淨 VM/實機安裝 | 三平台可安裝啟動 |
| 附加 | 資源 | 啟動時間 / 閒置記憶體 / 安裝包大小 | 啟動 ≤ 2s、閒置 ≤ 300 MB |

**評分表**（Spike 後填，1–5 分）：見 [`adr/0001-stack.md`](adr/0001-stack.md)。

**決策門檻**：

- Rust 總分 ≥ 4.0 且無致命缺陷 → 直接選 Rust。
- Rust 出現致命缺陷（如某平台熱鍵/注入無法解決）→ 跑 Go，比較後二選一。
- 三棧皆不達標 → 縮小平台範圍（例如先只做 Windows），而不是硬撐三平台。

## 8. 跨平台差異清單

> 📌 已寫進 [`../AGENTS.md`](../AGENTS.md) §6，實作前必看。

| 平台 | 錄音 | 熱鍵 | 文字注入 | 權限/打包 |
|---|---|---|---|---|
| Windows | WASAPI | 全域 hook | SendInput / 剪貼簿貼上 | 麥克風隱私設定；防毒白名單；建議簽章 |
| macOS | CoreAudio | CGEvent | Accessibility API / 貼上 | TCC：麥克風 + 輔助使用；notarization |
| Linux X11 | ALSA/PulseAudio | X11 | XTEST / 貼上 | 加入 `audio` 群組 |
| Linux Wayland | PipeWire | 依合成器 | **受限**，需 wtype/ydotool 或 portal | UI 顯示警告與指引 |

## 10. ASR 範圍與模型選擇（只做語音轉文字）

| 層級 | 選擇 | 說明 |
|---|---|---|
| 引擎 | sherpa-onnx（三棧皆可用其 C API） | 中文 Paraformer、英文 Zipformer；CPU 即時 |
| 備選 | whisper.cpp（Go/Rust）、faster-whisper（Python） | 多語言，但中文速度/記憶體略遜 |
| VAD | Silero VAD | 只做頭尾修剪，按鍵已決定錄音起訖 |
| 後處理 | 熱詞替換表 + 標點保留 | **不做 LLM** |
| 模型管理 | 使用者自放模型檔、設定頁填路徑 | 第一版不做自動下載 |

**雲端 ASR（選配，不做也可）**：預留 `SpeechEngine` 介面，未來可加 OpenAI/Azure/Deepgram/阿里雲/豆包，但 v1 默認全本地。

## 11. 風險登記冊

| 風險 | 機率 | 影響 | 對策 |
|---|---|---|---|
| 裝置按鍵送的鍵碼非常規（如多媒體鍵） | 中 | 中 | P0 鍵碼記錄；熱鍵綁定支援任意鍵 |
| **原廠工具（閃電說）會直接打字、注入按鍵、搶佔按鈕** | **已發生** | **高** | **P0 已確認；需決定「取代 or 並存」、偵測並要求關閉、以原生鍵碼為準** |
| **按鈕是 Enter/Backspace/方向鍵，會漏進前景視窗** | **已發生** | **高** | **熱鍵層必須抑制按鍵（低階 hook 回傳非 0），且需與 Raw Input 做裝置關聯** |
| **裝置按鈕無明確 PTT 鍵** | **已發生** | **中** | **由使用者指定語音鍵；設定頁支援任意鍵綁定** |
| 裝置本身會直接打字（內建辨識） | 低 | 高 | 架構分支：透傳模式；或關閉裝置內建功能 |
| **HFP 只提供 8 kHz，ASR 準確率不足** | **中** | **高** | **P0 實測取樣率；確認 mSBC 寬頻；否則放寬門檻或改用近場麥克風** |
| Wayland 文字注入受限 | 高 | 中 | 剪貼簿貼上優先；文檔指引；UI 警告 |
| macOS TCC 權限阻擋 | 中 | 高 | 首次啟動權限引導頁；notarization |
| Windows 防毒誤報（尤其 Python 打包） | 高 | 中 | Rust 正式版簽章；白名單說明 |
| onnxruntime 跨平台捆綁出錯 | 中 | 中 | 每個平台在 CI 產物中驗證模型載入 |
| Go cgo 交叉編譯失敗 | 高（Go 棧） | 高 | 三平台各自原生編譯，不做交叉編譯；失敗即淘汰 |
| 中文口音/台灣用語辨識率不足 | 中 | 中 | 熱詞表 + 測試集覆蓋；備選 Whisper 模型 |
| 低階機延遲超標 | 中 | 中 | int8 量化模型；按鍵模式本就允許 1–2 秒 |

## 12. 最終驗收標準（v1.0 發布條件）

1. 三平台皆完成：**配對麥克風 → 按住按鍵 → 說一句 → 放開 → 文字出現在記事本 → 錄音檔刪除**
2. 20 句測試集中文準確率 ≥ 95%，端到端延遲 ≤ 1.5 秒（5 秒語音）
3. 剪貼簿內容在注入後完整還原
4. 設定（裝置、按鍵、熱詞、模型路徑）重開後仍生效
5. 無網路環境下（本地模型）全功能可用
6. 安裝包：Windows `.exe/.msi`、macOS `.dmg`、Linux `.AppImage/.deb/.rpm`
